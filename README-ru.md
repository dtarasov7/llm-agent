# Coding Agent 1.2.0

CLI-агент для локальных LLM с совместимым с OpenAI API, реализованный в одном файле. Создаёт и изменяет код, исследует ошибки и запускает разрешённые проверки. Приложение использует Python 3.8+ и стандартную библиотеку.

[English README](README.md) · [Руководство пользователя](UserGuide-ru.md) · [История изменений](CHANGELOG-ru.md)

По умолчанию задача и каждое /continue получают по 500 обращений к LLM. Настройка: `--max-steps N`, `--continue-steps N`; в сеансе: `/max-steps [N]`, `/continue-steps [N]`. Команды в русской раскладке распознаются автоматически (например, `.й` как `/q`); аргументы в русской раскладке также исправляются.

Сообщения пользователя и отправка из `/edit` продолжают текущий диалог: можно попросить сохранить предыдущий ответ в файл. Для отдельной задачи выполните `/new`, после перезапуска — `/resume` для восстановления переписки.

Профили LLM привязаны к backend: /profile показывает фактические настройки, /profile fast отключает reasoning, /profile deep применяет настройки анализа. Для Strata fast, balanced и deep сохраняют выбранную модель и задают max_tokens=8192; balanced использует medium и бюджет рассуждений 2048, deep — high без отдельного бюджета. Ручные переопределения отображаются как modified.

Профили Strata настроены по [рекомендациям Qwen3.8-Flash-Next](https://huggingface.co/unsloth/Qwen3.8-Flash-Next-GGUF#best-practices): fast — temperature=0.7, top_p=0.80, top_k=20, min_p=0.0, presence_penalty=1.5, repetition_penalty=1.0; deep — temperature=1.0, top_p=0.95, top_k=20, min_p=0.0, presence_penalty=0.0, repetition_penalty=1.0. При переключении профиль заменяет все эти параметры. Допустимы temperature 0..2, top_p >0 и ≤1, top_k — целое 1..64, min_p 0..1, presence_penalty 0..2 и конечный repetition_penalty >0. Для других моделей настройте профили отдельно. Эти настройки не гарантируют устранение циклов; presence_penalty может вызывать смешение языков и снижение качества. balanced использует те же параметры sampling, что и deep. /profile balanced задаёт effort=medium и бюджет рассуждений 2048; /profile deep — effort=high и reasoning_budget_tokens=0 (без отдельного бюджета). Общий max_tokens=8192 включает рассуждения и ответ. Сравнивайте время всей задачи, число исправлений и суммарные токены: короткие ответы могут увеличивать число повторных попыток. Модель может исчерпать общий лимит до формирования вызова инструмента. Агент не меняет reasoning_loop_recovery и YaRN на сервере.

### Ollama

Запуск: `python coding_agent.py --workspace /path/to/project --backend ollama --model YOUR_MODEL`. Адрес по умолчанию http://127.0.0.1:11434; измените BACKENDS для удалённого сервера. Модель должна быть установлена и поддерживать вызовы инструментов. /model показывает доступные идентификаторы.

Профиль fast активен по умолчанию и отключает thinking через reasoning_effort=none. /profile deep сохраняет модель, задаёт low, temperature=0.6, top_p=0.95 и max_tokens=8192. Управление thinking зависит от модели и версии Ollama. /thinking on без заданного effort использует medium; /thinking auto оставляет параметры профиля. Отдельный reasoning-бюджет и top_k через OpenAI-совместимый адаптер не передаются; такие поля профиля отклоняются.

Для статистики рабочего контекста задайте --context-window N: адаптер не считает обучающий предел модели фактическим контекстом Ollama. Этот параметр не меняет настройки сервера. Документация API: [Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility).

## Возможности

- Адаптеры llama.cpp, vLLM, Strata и Ollama; переключение моделей и профилей LLM без перезапуска.
- Адресный просмотр файлов, чтение UTF-8, поиск подстрок и регулярных выражений, создание файлов и точная замена блоков.
- Изолированная рабочая копия, просмотр различий, восстановление начальной базы и перенос в оригинал по подтверждению пользователя.
- Временные снимки проверок в Linux bubblewrap; переносимый режим работает без пользовательской службы systemd, строгий проверяет общие лимиты cgroup.
- Компиляция Python, unittest, pytest, синтаксис Bash, ShellCheck, синтаксис Ansible и автономный Ansible lint.
- Режимы AUTO/REVIEW, ограниченный цикл, защита от повторов, сохранение задач и автоматическое восстановление неприменённых изменений после перезапуска.
- История readline, перемещение курсора, дополнение TAB, многострочная вставка из буфера обмена, подробный ход инструментов и статистика токенов и контекста.
- `/edit` открывает редактор задачи в терминале: Alt+Enter запускает задачу, два Esc отменяют, Ctrl+P/Ctrl+N переключают черновики.

## Требования

Нужны системный Python в `/usr`, непривилегированная учётная запись Linux, доверенная утилита `bwrap` владельца root и доступные непривилегированные пространства имён. Режим по умолчанию `--sandbox portable` не требует пользовательской службы systemd и делегирования cgroup. Для `--sandbox strict` дополнительно нужны доверенные `systemd-run`/`systemctl`, доступный менеджер пользователя и контроллеры cgroups v2 для памяти, процессов и CPU. `/security` проверяет выбранный режим и его фактическую доступность. При недоступности изоляции проверки не запускаются.

Сервер LLM должен поддерживать структурированные вызовы инструментов. Необязательные утилиты должны быть заранее установлены в доверенных системных каталогах: `bash`, `shellcheck`, `ansible-playbook`, `ansible-lint`; pytest должен быть доступен системному Python внутри изоляции. Агент не устанавливает зависимости автоматически. Интерактивное редактирование требует стандартного модуля `readline` и терминала.

Для редактирования многострочной задачи выполните `/edit` в интерактивном терминале с поддержкой стандартного модуля Python `curses`. Редактор занимает нижнюю половину экрана; заголовок по центру и подсказка расположены на рамке из линий. Enter добавляет строку; вставка выполняется обычным сочетанием клавиш терминала. Alt+Enter закрывает редактор, выводит полный текст задачи и запускает её. Два нажатия Esc закрывают окно без исполнения; непустой черновик сохраняется и при отмене. Ctrl+P/Ctrl+N переключают отдельную историю редактора, сохраняя текущий черновик на время просмотра.

## Быстрый запуск

Настройте `BACKENDS` и `LLM_PROFILES` в начале [coding_agent.py](coding_agent.py): укажите адрес сервера и реальные идентификаторы моделей. Поставляемые адреса являются примерами для частной локальной сети.

```bash
python3.8 coding_agent.py --version
python3.8 coding_agent.py --workspace /path/to/project --backend home-llama --model qwen36-fast
python3.8 coding_agent.py --workspace /path/to/project --sandbox strict  # необязательные общие лимиты ресурсов
```

При запуске выводятся `Coding Agent 1.2.0`, пути оригинала и рабочей копии, состояние сеанса и безопасности. Каталог состояния должен находиться отдельно, вне исходного проекта; при необходимости задайте `--state-dir /path/to/private-state`.

Повторный запуск с теми же `--workspace` и `--state-dir` автоматически подключает последнюю сохранённую копию, если в ней есть неприменённые изменения. После этого `/apply` показывает список файлов с числами добавленных и удалённых строк и переносит их только после подтверждения. Для намеренного создания новой копии используйте `--new-session`; `/resume` остаётся для ручного восстановления задачи.

```text
/security
/model
/mode review
Добавь параметр --timeout в backup.py и обнови соответствующие тесты.
/task
/diff
/check python_compile backup.py
/check unittest tests
/apply
```

После остановки задачи, в том числе при заблокированной проверке, приложение показывает абсолютный путь каждого изменённого файла рабочей копии и число добавленных и удалённых строк (`+N -M`). Полный diff автоматически не выводится. Команда `/diff` показывает правки текущей задачи, `/diff path/to/file.py` — один файл задачи, а `/diff --session` — все изменения с начала сеанса. Можно также вставить показанный абсолютный путь. Путь с пробелами заключайте в кавычки. `/apply` показывает только имена файлов и числа строк, затем запрашивает подтверждение перед переносом. Ошибка изоляции сохраняет файлы рабочей копии.

`/apply` показывает неприменённые изменения и ожидает `y`; иначе оригинал остаётся без изменений. `AUTO` разрешает правки только рабочей копии. `/revert` немедленно восстанавливает всю копию до начальной базы сеанса. Команда не отменяет изменения, уже перенесённые в оригинал.

## Навыки

Проектные skills находятся в `.agents/skills/<имя>/SKILL.md` целевого workspace. Файл содержит заголовок YAML с `name`, совпадающим с каталогом, и `description`, затем инструкции Markdown. `/skills` показывает каталог, `/skills имя` — текст навыка. Укажите `$имя` в задании для явной загрузки либо позвольте модели выбрать подходящий навык из краткого каталога через `read_skill`. Вспомогательные тексты читаются внутри каталога навыка. Действуют существующие ограничения проекта и изоляции. Формат и примеры описаны в [руководстве](UserGuide-ru.md#проектные-skills).

## Проверки

| Проверка | Назначение |
| --- | --- |
| `python_compile` | Компиляция выбранных файлов Python. |
| `unittest` | Поиск тестов в одном каталоге; отсутствие тестов считается ошибкой. |
| `pytest` | Запуск pytest системным Python. |
| `bash_syntax` | Отдельный `bash -n` для каждого файла. |
| `shellcheck` | Статический анализ shell без загрузки rc и перехода к внешним source. |
| `ansible_syntax` | Проверка playbook либо временного wrapper роли с закрытыми inventory/config. |
| `ansible_lint` | Автономный lint с контролируемыми конфигурациями Ansible и lint. |

Результаты различают `PASS`, `FAIL`, `SKIPPED`, `TIMEOUT`, `SANDBOX_ERROR` и `INVALID_TARGET`. Отсутствующие внешние утилиты статических проверок дают `SKIPPED`. Синтаксис и lint не доказывают функциональную корректность, успешное развёртывание или идемпотентность Ansible. Для Ansible lint применяется [автономный режим](https://docs.ansible.com/projects/lint/configuring/), запрещающий установку requirements и обновление схем.

## Настройка и серверы

```python
BACKENDS = {
    "home-llama": {"type": "llama.cpp", "url": "http://127.0.0.1:12345",
                   "api_key": None, "model": None},
    "vllm": {"type": "vllm", "url": "http://127.0.0.1:8000",
             "api_key_env": "VLLM_API_KEY", "model": None},
}
LLM_PROFILES = {
    "strata": {
        "fast": {"model": None, "thinking": "off", "max_tokens": 8192,
                 "temperature": 0.7, "top_p": 0.80, "top_k": 20,
                 "min_p": 0.0, "presence_penalty": 1.5, "repetition_penalty": 1.0},
        "balanced": {"model": None, "thinking": "on", "reasoning_effort": "medium",
                     "reasoning_budget_tokens": 2048, "max_tokens": 8192,
                     "temperature": 1.0, "top_p": 0.95, "top_k": 20,
                     "min_p": 0.0, "presence_penalty": 0.0, "repetition_penalty": 1.0},
        "deep": {"model": None, "thinking": "on", "reasoning_effort": "high",
                 "reasoning_budget_tokens": 0, "max_tokens": 8192,
                 "temperature": 1.0, "top_p": 0.95, "top_k": 20,
                 "min_p": 0.0, "presence_penalty": 0.0, "repetition_penalty": 1.0},
    },
}
```

Для llama.cpp включите вызовы функций через `--jinja` и подходящие модель и шаблон чата: [официальное руководство llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/docs/function-calling.md). Для vLLM настройте автоматический выбор инструментов и совместимый с моделью обработчик: [официальное руководство vLLM](https://docs.vllm.ai/en/latest/features/tool_calling/). Инструменты агента выполняются самим приложением.

Используйте `--context-window TOKENS`, если сервер не сообщает предел контекста. Ограничения файлов, вывода, итераций и изоляции задаются константами `coding_agent.py`; значения и последствия описаны в руководстве.

Перед запросом LLM выводится краткая суть задачи. Потоковый приём SSE по умолчанию показывает каждые 5 секунд время ожидания и счётчики данных без содержимого ответа. Лимит одного ответа — 8192 токена (`--max-tokens N`, `/max-tokens N`). Обрезанные ответы не выполняют инструменты и не повторяются автоматически; продолжение — `/continue`. `--llm-timeout` задаёт ожидание сокета (600 секунд), `--no-stream` включает совместимость с непотоковыми серверами. После перезапуска восстановите задачу через `/resume`. Некорректный JSON аргументов также отклоняется целиком; /continue передаёт модели инструкцию уменьшить правку и исправить JSON.

Диагностика LLM отдельно показывает число полученных символов рассуждений, текста ответа и аргументов инструментов (не токенов). Во время потока и при завершении, обрыве или отмене выводятся имена начатых вызовов, включая неполные имена; их содержимое не печатается. Идентификаторы вызовов не входят в счётчики. Нулевой счётчик рассуждений означает, что отдельные поля reasoning/reasoning_content не получены: если сервер смешивает рассуждения с content, они учитываются как текст. Для обычного JSON эти сведения доступны только после получения ответа. Начатый вызов не означает выполненный инструмент.


Переносимый режим ограничивает адресное пространство, процессорное время, открытые файлы и размер файла для каждого процесса, а также время всей проверки. Общих лимитов памяти, CPU и числа процессов в нём нет. У закрытого `/tmp` нет отдельной жёсткой квоты при синтаксисе, поддерживаемом bubblewrap 0.6.3. Строгий режим добавляет проверенные общие лимиты cgroup. Оба режима запускают проверки только внутри bubblewrap.

## Проверка реализации

```bash
python3.8 -B coding_agent.py --self-test
```

Self-test не требует сервера LLM. Интеграционные тесты пропускаются при отсутствии утилиты либо подтверждённой изоляции; пропуск не означает запуск проверки. На текущей машине реальные интеграционные проверки переносимого режима проходят без делегирования `cpu.max` пользовательской службе; тест общих лимитов строгого режима и отсутствующий `ansible-lint` пропущены.

### Контекст и AGENTS.md

Загрузка корневого `AGENTS.md` отображается при запуске задачи; `/context` показывает сохранённые инструкции и статистику. `/compact` сжимает переписку текущей задачи через LLM, сохраняя инструкции проекта и skills, цель, состояние файлов и проверок. Полная переписка архивируется. Продолжение — `/continue`. Подробности: [UserGuide-ru.md](UserGuide-ru.md).

### Strata

Выбирайте `--backend strata`; запись сервера должна иметь `"type": "strata"`. Адаптер использует Chat Completions, SSE и локальное выполнение инструментов; предел контекста читает из `meta.n_ctx`. `/thinking off` поддерживается. Проверка совместимости выполнена по [документации Strata](https://github.com/Niko1221/Strata/blob/main/docs/DETAILS.md) и [исходному коду API](https://github.com/Niko1221/Strata/blob/main/serve/server.py), с тестами формата ответов. Живая проверка 7 октября 2026 года прошла: модель qwen3.8-flash-next-iq3_xxs, контекст 131072, JSON/SSE, вызов инструмента и управление reasoning. Первоначальная попытка соединения получила Connection refused; повторная проверка прошла.
